# 用户交互与位号确认

## 交互原则（Cursor 环境）

- **流程**：加载本技能后严格按 `SKILL.md` 工作流执行（见「绝对执行原则」）；本文件只规定确认文案与轮次
- 用中文向用户提问；每次不超过 4 个问题
- 提供可选建议 +「我来手动填写」
- **不要依赖 AskUserQuestion / PureShowWidget**（环境可能无此工具）
- 用对话列表、表格、编号选项完成确认
- 任何会改平台状态的 API：`create` / `compile` 必须先得到用户明确同意；**`save_program` 在 Step 3 校验通过后自动执行，不与用户确认**
- **确认已合并**：整流程只保留本文件下列确认轮次，禁止再拆成多轮重复问

## 确认轮次（仅 4 轮）

| 轮次 | 步骤 | 内容 |
|------|------|------|
| ① | 1.5 | **仅**拆不拆 +（若拆）子程序 name/描述表 |
| ② | 2 | **仅**分组 + 主程序字段 → 同意创建 |
| ③ | 2.5 | 位号与缺失信息（单独，不与其它合并） |
| ④ | 3.5 | **仅**编译二选一（保存不询问） |

**硬隔离（1.5 ↔ 2）：**  
「是否拆分」与「创建程序」必须 **严格分开、单独交互**——两轮对话、两段确认；**禁止**同一条消息/同一屏同时问拆分方案与创建字段；未完成 1.5 用户确认前，**禁止**展示或索要 Step 2 的分组/program_name/同意创建。

## Step 1.5：拆分方案（原 1.5 + 2.1 合并）

**本轮只确认拆分，不涉及创建程序。**

**一次确认**，包含：

1. 选项：**不拆分** / **拆分**（可标注推荐 + 一句理由）
2. 若倾向或选择**拆分**，同屏展示子程序草案（不拆分则不展示或注明「无」）：

| # | name | 描述/职责 |
|---|------|-----------|
| 1 | load_down | 降负荷相关操作 |
| 2 | stop_fan | 停风机相关操作 |

3. 用户可改：拆/不拆、name、描述、合并/删减行；name 规则见 `subprocess.md`
4. 用户确认本步后，才进入 Step 2；**不要**在创建后再单独开一轮问子程序表
5. **禁止**在本轮询问/展示：分组、program_name、description、version、group_id、同意创建

写入 `flow:subproc` 的 name / subTitle / subId 规则见 **`subprocess.md` §flow:subproc**。  
`get_next_id`：在 Step 2 `create_program` **成功之后**、进入 2.5 **之前**执行（本步只定草案，不调 API）。

## Step 2：创建主程序（一次确认）

**本轮只确认创建；拆分方案已在 1.5 敲定，本轮不再重开拆/不拆讨论（除非用户主动要求改）。**

1. 调用 `get_data_groups()`，默认选中 `groupId == "1001"` 对应分组名
2. **同一屏**展示全部分组 + 主程序字段，一次请用户确认：

| 字段 | 规则 | 默认 |
|------|------|------|
| program_name | 命名见 `subprocess.md`（与子程序/timers/variables 同规则） | 由 SOP 标题转写 |
| description | 无限制 | 可空 |
| version | 无限制 | v1.0 |
| group_id | 来自分组列表 | 1001 |

3. 用户明确同意后才调用 `create_program`
4. 若 Step 1.5 为**拆分**：创建成功后立即 `get_next_id` × N，写入 IR/`flow:subproc`（见 `subprocess.md`），**不再**另开确认轮
5. **禁止**使用 `deploy_program`
6. **禁止**把「是否拆分 / 子程序表」并入本轮提问

## Step 2.5：位号与缺失信息（强制，单独一轮）

无论 SOP 是否已有位号，都必须汇总确认。**禁止**与 1.5 / 2 / 3.5 合并。

子程序场景顺序：主程序位号（通常可跳过）→ 逐个子程序位号。

### 位号确认清单格式

| # | 步骤 | 用途 | 建议位号 | type | 用户确认值 |
|---|------|------|----------|------|------------|
| 1 | Step3 启泵 | MANON | P0801A_MANON | 3 | |

type：取值见 `node_reference.md` §二（唯一来源：`1` / `3`）

### 位号填写方式

1. 用户直接回复修正值  
2. `get_tags` / `search_tags_by_name` 列候选供选  
3. 从 SOP 原文再核对  

写入 IR/`#()`/`$()` 格式：**唯一来源** `node_reference.md` §一。

### 其他缺失项

- 参数值 / 安全阈值 / 模糊描述 → 请用户补全  

全部确认并写回 IR 后才能进入 Step 3。

## Step 3.5：自动保存 + 编译二选一（原 3.7 + 4 + 4.5 合并）

前置：Step 3 已对主（及拆分时全部子）`ir_to_xml` + `validate_bpmn.py main.xml [sub….xml]` 退出码 0；`accuracy_checklist.md` 已勾选。

**保存：不与用户交互，但必须成功后才能向下。**  
前置满足后直接调用 `save_program`（拆分必须带齐 `subprograms[].xml_content`，见 `subprocess.md`）。禁止再问「是否同意保存」。

### 保存成功判定（硬门禁）

以 API 返回为准（`api_reference.save_program` / `_check_response_code`）：

| 字段 | 成功条件 | 说明 |
|------|----------|------|
| `code` | 必须存在且为 `0` 或 `"0"` | 缺 `code`、非 0 → **保存失败** |
| `msg` / `message` | 失败时用于展示 | 优先读 `msg`，其次 `message` |

- **成功**：方可展示结果并进入编译二选一  
- **失败**：向用户展示 `code=…；msg=…`（或脚本抛出的同等文案），**停止本步**；禁止问编译、禁止调用 `compile_program`、禁止假装已保存进入 Step 5/6  
- 脚本已在 `code≠0` / 缺 `code` 时抛错；Agent 不得吞掉异常继续往下

**本轮唯一交互**是编译选择。流程：

1. 自动 `save_program` → 仅当 `code` 成功才进入下一步  
2. 保存成功后展示简要结果（程序名、appid、节点/连线数；拆分时注明主+子已保存），**只允许**下面两种回复：

```
请选择：
1. 确认编译
2. 暂不编译
```

| 用户选择 | 动作 |
|----------|------|
| `1` / `确认编译` | 调用 `compile_program(主 appid)`（同样以 `code`/`msg` 判定） |
| `2` / `暂不编译` | 不编译，进入结果报告 |

未收到上述选项之一前，禁止调用编译接口。  
可在保存成功的同一条消息里给出编译二选一（仍算本步，不另开 Step）。
