# 用户交互与位号确认

## 交互原则（Cursor 环境）

- 用中文向用户提问；每次不超过 4 个问题
- 提供可选建议 +「我来手动填写」
- **不要依赖 AskUserQuestion / PureShowWidget**（环境可能无此工具）
- 用对话列表、表格、编号选项完成确认
- 任何会改平台状态的 API（create / save / compile）必须先得到用户明确同意

## Step 1.5：是否拆分（仅此一项）

只问：

- **不拆分**
- **拆分**（若评估可拆，可标注推荐）

可附一句推荐理由；**不要**在此步展示子程序名称/描述表。

## Step 2：创建主程序前确认

1. 调用 `get_data_groups()`，默认选中 `groupId == "1001"` 对应分组名
2. 向用户展示全部分组，请其选择
3. 展示并确认主程序字段：

| 字段 | 规则 | 默认 |
|------|------|------|
| program_name | 字母开头；仅 `[A-Za-z0-9_]`；禁止中文 | 由 SOP 标题转写 |
| description | 无限制 | 可空 |
| version | 无限制 | v1.0 |
| group_id | 来自分组列表 | 1001 |

4. 用户明确同意后才调用 `create_program`
5. **禁止**使用 `deploy_program`

## Step 2.1：子程序信息（仅拆分，创建成功后）

当 Step 1.5 选择**拆分**且主程序已创建成功时：

1. AI 根据 SOP 生成子程序草案并展示：

| # | name | 描述/职责 |
|---|------|-----------|
| 1 | load_down | 降负荷相关操作 | 
| 2 | stop_fan | 停风机相关操作 | 

2. 用户可改 name / 描述 / 合并拆分条目；name 规则同 program_name（`[A-Za-z][A-Za-z0-9_]*`）  
3. 用户确认后，再 `get_next_id` × N  
4. 写入主程序 `flow:subproc` 的规则见 **`subprocess.md` §flow:subproc**（name / subTitle / subId）  
5. 若 Step 1.5 选**不拆分**：跳过本步，直接进入 Step 2.5  

## Step 2.5：位号与缺失信息（强制）

无论 SOP 是否已有位号，都必须汇总确认。

子程序场景顺序：主程序位号（通常可跳过）→ 逐个子程序位号。

### 位号确认清单格式

| # | 步骤 | 用途 | 建议位号 | type | 用户确认值 |
|---|------|------|----------|------|------------|
| 1 | Step3 启泵 | MANON | P0801A_MANON | 3 | |

type：取值见 `node_reference.md` §二（唯一来源：`1` / `3`）

### 位号填写方式

1. 用户直接回复修正值  
2. `get_tags` / `search_tags_by_name` 列候选供选  
3. 从 SOP 原文再核对  

写入 XML 时的 `#()` / `$()` 格式：**唯一来源** `node_reference.md` §一。

### 其他缺失项

- 参数值 / 安全阈值 / 模糊描述 → 请用户补全  

全部确认后才能进入 Step 3。

## Step 4.5：是否编译（固定选项，始终如此）

保存成功后展示简要结果（程序名、appid、节点/连线数），然后**只允许**下面两种回复，禁止开放式提问：

```
请选择：
1. 确认编译
2. 暂不编译
```

| 用户选择 | 动作 |
|----------|------|
| `1` / `确认编译` | 调用 `compile_program(主 appid)` |
| `2` / `暂不编译` | 不编译，进入结果报告 |

未收到上述选项之一前，禁止调用编译接口。
