# 用户交互与位号确认

## 交互原则（Cursor 环境）

- 用中文向用户提问；每次不超过 4 个问题
- 提供可选建议 +「我来手动填写」
- **不要依赖 AskUserQuestion / PureShowWidget**（环境可能无此工具）
- 用对话列表、表格、编号选项完成确认
- 任何会改平台状态的 API（create / save / compile）必须先得到用户明确同意

## Step 2：创建主程序前确认

1. 调用 `get_data_groups()`，默认选中 `groupId == "1001"` 对应分组名
2. 向用户展示全部分组，请其选择
3. 展示并确认：

| 字段 | 规则 | 默认 |
|------|------|------|
| program_name | 字母开头；仅 `[A-Za-z0-9_]`；禁止中文 | 由 SOP 标题转写 |
| description | 无限制 | 可空 |
| version | 无限制 | v1.0 |
| group_id | 来自分组列表 | 1001 |

4. 用户明确同意后才调用 `create_program`
5. **禁止**使用 `deploy_program`（会跳过确认并自动编译）

## Step 2.5：位号与缺失信息（强制）

无论 SOP 是否已有位号，都必须汇总确认。

子程序场景顺序：主程序位号（通常可跳过）→ 逐个子程序位号。

### 位号确认清单格式

每条必须包含：所属步骤、用途、建议位号、type 建议。

```
| # | 步骤 | 用途 | 建议位号 | type | 用户确认值 |
|---|------|------|----------|------|------------|
| 1 | Step3 启泵 | MANON | P0801A_MANON | 3 | |
```

type：`1` 浮点（温度/压力/流量）· `2` 整型 · `3` 数字量/开关/阀位

### 位号填写方式

1. 用户直接回复修正值
2. Agent 调用 `get_tags` / `search_tags_by_name`，列出候选供用户选择（分页展示 name/type/remark）
3. 从 SOP 原文再核对

写入 XML 时 **必须** `#()` 包裹，例如 `#(HIC_V1001A_1.MANON)`。  
程序变量用 `$(VAR)`。

### 其他缺失项

- 参数值缺失（「适当温度」）→ 请用户给数值
- 安全阈值缺失 → 请用户给阈值与联锁动作
- 模糊描述 → 请澄清为可量化条件

全部确认后才能进入 Step 3 生成 XML。
