# 用户交互与位号确认

## 交互原则

- **流程**：加载本技能后严格按 `SKILL.md` 工作流执行（见「绝对执行原则」）；本文件只规定确认文案与轮次
- 用中文向用户提问；每次不超过 4 个问题
- 提供可选建议 +「我来手动填写」
- **交互载体**：对话正文为主；Step 2.5 **本机 HTTP 打开可编辑页**（可点的 `http://127.0.0.1:…/`）；系统负责 JSON/HTML/服务；**用户未在浏览器点「提交确认」前禁止进入 Step 3**；禁止依赖宿主专用 Ask/单选 SDK；**禁止**把 HTML 内嵌进对话/工作流
- 任何会改平台状态的 API：仅 **`compile` 前须用户明确同意**；**`create_program` / `save_program` 不询问用户**（字段按本文件规则自动填）
- **平台调用唯一入口**：只使用 `scripts/api_reference.py` 的 `DirectPlatformClient`（`create_program` / `save_program` / `compile_program` / `get_data_groups` / `get_next_id` / `get_tags` 等）。**禁止**自行拼 URL、手写 `addProcedures`/`updateProcedures` payload、用 curl/裸 `requests` 调 Direct
- **确认已合并**：整流程只保留本文件下列确认轮次，禁止再拆成多轮重复问

## 确认轮次（仅 3 轮）

| 轮次 | 步骤 | 内容 |
|------|------|------|
| ① | 1.5 | **仅**对话编号二选一：不拆分 / 拆分 + **唯一推荐**（不问子程序 name/描述） |
| ② | 2.5 | 打开 `http://127.0.0.1:…/` → 改位号/type/设定值 → **提交确认**（未确认不往下） |
| ③ | 3.5 | **仅**编译二选一（创建与保存均不询问） |

**说明：** Step 2 创建主程序 **无用户交互**（见下）。1.5 确认前禁止创建；1.5 确认后直接进入 Step 2 自动创建，再进 2.5。

---

## Step 1.5：拆分方案

**本轮仅与用户交互「拆 / 不拆」**（须标推荐）。不涉及创建程序、不问子程序 name/描述。

### 硬门禁（严格）

- **本轮唯一问题**：是否拆分子程序；**禁止**在本轮索要或请用户填写子程序 name、描述、合并删减行
- **只许对话编号二选一**；禁止宿主单选/下拉控件
- **必须**同时写出两个选项；未收到用户明确回复（`1`/`2` 或「不拆分」/「拆分」）前 **禁止**进入 Step 2
- **必须**按 `subprocess.md` 评估，恰好一项标 `（推荐）`，并附一句理由；禁止不标、禁止两项都标、禁止默认代选、禁止跳过

**强制文案模板（本轮正文仅此，勿夹带 name/描述填写表）：**

```
请选择是否拆分子程序（二选一，请直接回复 1 或 2）：
理由：…
1. 不拆分（推荐）
2. 拆分
```

（若推荐拆分：把 `（推荐）` 写在第 2 项，第 1 项不带。）

### 用户选定「拆分」之后（无交互）

1. 按评估边界把 SOP **划分成若干子文档/子段落**（每子一份连续原文职责块）
2. **子程序 name、描述尽量根据该子划分文档内容生成**（从主题/设备/操作提炼；name 仅 `[A-Za-z0-9_]`；描述写入 `subTitle` 且可读）；禁止空洞占位名与无关套话；**禁止**再请用户填写或确认；**各子 name 必须互不重复**（亦不得与主程序名相同；撞名则自动加 `_2`、`_3`…）
3. 可向用户**只读展示**生成结果（可选），但不得阻塞等待用户改名
4. 然后进入 Step 2 自动创建；`get_next_id` 在 create 成功后、2.5 前执行（见 `subprocess.md`）

### 禁止

- 在本轮询问创建字段或「同意创建」
- 未展示二选一就往下；未标推荐；把推荐当成已确认
- 依赖用户填写子程序 name/描述

## Step 2：创建主程序（无交互，自动执行）

**本步不向用户提问、不展示确认表、不等待同意。** 仅在 Step 1.5 用户已明确选择拆/不拆之后执行。

1. 调用 `get_data_groups()`（用于校验默认分组是否存在）
2. 按下列规则**自行填齐字段**后直接 `create_program`：

| 字段 | 取值规则 |
|------|----------|
| program_name | **优先从对话提取**用户已给出的程序名（规范为 `[A-Za-z0-9_]`）；提取不到 → **结合 SOP/文档标题与内容生成** |
| description | **优先从对话提取**；提取不到 → **结合文档内容生成**（不得空串凑合；应能概括规程主题） |
| version | **优先从对话提取**；提取不到 → 默认 `v1.0` |
| group_id | **优先从对话提取**；提取不到 → 默认 `"1001"`（若分组列表无此 id，改用列表第一项并在报告中说明） |

3. **禁止**就上述字段再开一轮询问或请用户确认
4. 若用户选定**拆分**：创建成功后立即 `get_next_id` × N；子程序 **name / 描述** 已由 Agent 按各子文档内容生成（见 Step 1.5 / `subprocess.md`），写入 IR/`flow:subproc`
5. **禁止**使用 `deploy_program`
6. 创建成功后直接进入 Step 2.5（位号确认）

## Step 2.5：位号与缺失信息（强制，单独一轮）

无论 SOP 是否已有位号，都必须汇总确认。**禁止**与 1.5 / 2 / 3.5 合并。

### 硬门禁（严格）

- **用户未在浏览器点击「提交确认」之前，禁止进入 Step 3**（禁止 `ir_to_xml` / 生成 XML / save）
- 必须以 `serve_tag_confirm.py` **退出码 0** 为已确认依据；脚本在收到合法 POST 前会阻塞；超时/中断/非 0 → **停止本步**，不得假装已确认继续
- 禁止用「用户口头说确认了」或贴 JSON 替代浏览器提交

### 职责划分

| 谁 | 做什么 |
|----|--------|
| **系统** | 预写 JSON → 启动 `serve_tag_confirm.py`（生成 HTML、起本机服务、自动打开浏览器、**阻塞等待**）→ 退出码 0 后读确认 JSON → 写回 IR |
| **用户** | 在浏览器中 **仅**改「位号 / type / 设定值」并点「提交确认」 |

用户**不**手写 JSON、**不**跑脚本、**不**自己写 HTML。  
**禁止**新增/删除行；`id`/`program`/`step`/`usage`/`note` 只读。

### 契约与呈现

- 预写：`artifacts/<run>/tag_confirm.json`；确认后：同文件被服务端覆盖，并写 `tag_confirm.confirmed.json` + `.done`
- 呈现：对话给出可点击的 **`http://127.0.0.1:<port>/`**（脚本也会尝试自动打开）；**禁止**内嵌 HTML 正文
- **可改字段仅**：`tag`、`type`、`value`；三者提交时须完整非空；行数与锁定字段须与预写一致

### 系统强制步骤

1. **预写 JSON**：从 IR 生成预填 `artifacts/<run>/tag_confirm.json`（禁止 PLACEHOLDER）
2. **启动并阻塞等待浏览器确认**（本步核心硬门禁）：
   ```bash
   python -u scripts/serve_tag_confirm.py artifacts/<run>/tag_confirm.json \
     --html-out artifacts/<run>/tag_confirm.html \
     --confirmed-out artifacts/<run>/tag_confirm.confirmed.json
   ```
   - 向用户展示脚本打印的 `[URL]`；提示在浏览器改完后点「提交确认」
   - **在该命令退出码为 0 之前，禁止执行后续任何 Step 3 动作**
3. **写回 IR**：读取确认后的 JSON（`tag_confirm.confirmed.json` 或已覆盖的 `tag_confirm.json`）；按行合并结果已由服务端校验 → 写回 IR → 才进 Step 3

### 禁止

- 未等 `serve_tag_confirm.py` 退出码 0 就进 Step 3
- 把 HTML 内嵌进对话或工作流
- 允许用户新增/删除行，或改锁定字段；接受半填提交
- 把预写 JSON / 起服务说成用户步骤
- 默认退回「Markdown 清单 + 逐条文字改」或要求用户贴 JSON
- 本步或更早生成 XML

写入 IR 的 `#()`/`$()`：`node_reference.md` §一。

## Step 3.5：自动保存 + 编译二选一（原 3.7 + 4 + 4.5 合并）

前置：Step 3 已对主（及拆分时全部子）`ir_to_xml` + `validate_bpmn.py main.xml [sub….xml]` 退出码 0；`accuracy_checklist.md` 已勾选。

**禁止**跳过 Step 3 直接 save。`save_program` 内部会再验一遍 XML（结构、几何、全部元件 `ext` schema）；未通过则抛错、**不调用平台接口**。

**保存：不与用户交互，但必须先过本地校验、再保存成功后才能向下。**  
前置满足后直接调用 `save_program`（拆分必须带齐 `subprograms[].xml_content`，见 `subprocess.md`）。禁止再问「是否同意保存」。

### 保存成功判定（硬门禁）

以 API 返回为准（`api_reference.save_program` / `_check_response_code`）：

| 字段 | 成功条件 | 说明 |
|------|----------|------|
| `code` | 必须存在且为 `0` 或 `"0"` | 缺 `code`、非 0 → **保存失败** |
| `msg` / `message` | 失败时用于展示 | 优先读 `msg`，其次 `message` |

- **成功**：方可展示结果并进入编译二选一  
- **失败**：向用户展示 `code=…；msg=…`（或脚本抛出的同等文案），**停止本步**；禁止问编译、禁止调用 `compile_program`、禁止假装已保存进入 Step 5/6  
- 脚本已在 `code≠0` / 缺 `code` 时抛错；Agent 不得吞掉异常继续往下

**本轮唯一交互**是编译选择。流程：

1. 自动 `save_program` → 仅当 `code` 成功才进入下一步  
2. 保存成功后展示简要结果（程序名、appid、节点/连线数；拆分时注明主+子已保存），**只允许**下面两种回复：

```
请选择：
1. 确认编译
2. 暂不编译
```

| 用户选择 | 动作 |
|----------|------|
| `1` / `确认编译` | 调用 `compile_program(主 appid)`（同样以 `code`/`msg` 判定） |
| `2` / `暂不编译` | 不编译，进入结果报告 |

未收到上述选项之一前，禁止调用编译接口。  
可在保存成功的同一条消息里给出编译二选一（仍算本步，不另开 Step）。
